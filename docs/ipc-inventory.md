## Behaviour and trust notes

- All 311 `registerEvent` calls are top-level. There is no platform-conditional registration. Platform checks happen inside handlers (for example `autoLaunch`, `restartAndInstallUpdate`, and Linux-only UMU handlers).
- `src/main/events/register-event.ts` wraps `ipcMain.handle` and returns `JSON.stringify(result)` when the result is truthy. That means every handler result crosses the boundary as a JSON string, not as a structured clone; callers rely on the preload/`JSON.parse` convention. Any Tauri port must preserve this exact serialization contract or explicitly change every caller.
- Only the Epic handlers call `assertTrustedEpicSender`. There is no uniform sender validation across the other 300+ handlers. Tauri commands should add an allowlist/trust check rather than copying this pattern.
- The preload exposes `hydraApiCall`, which forwards an arbitrary path/method into the authenticated main-process API client. This is a renderer-controlled network primitive and must not be carried into Sphinx unchanged.
- `getGameArtifacts`, `pauseGameTransfer`, and `resumeGameTransfer` are stale preload APIs. Preserve only if the corresponding main handlers are restored; otherwise remove them from the new bridge.
